# AI Studio プレビュー環境における `stamps.js` 疎通チェック確認手順書

## 概要
AI Studio プレビュー環境および GitHub Pages/Synology NAS 環境において、`stamps.js`（スタンプ管理API）が正しく応答・処理を行っているか、ブラウザの開発者ツール（F12）を使って確認・診断する手順を案内します。

---

## 確認・検証手順 (F12 Developer Tools)

### 手順 1: ブラウザの開発者ツールを開く
1. キーボードの **`F12`** キー（Mac の場合は `Cmd + Option + I`）を押します。
2. 画面右側または下部に表示されたツールパネルから **「ネットワーク (Network)」** タブを選択します。
3. フィルター欄で **「Fetch/XHR」** を選択します。

### 手順 2: API 疎通レスポンスのテスト確認
1. 管理画面の **「スタンプ管理」** タブを開くか、更新ボタンを押します。
2. ネットワークタブの一覧に **`stamps`** というリクエストが表示されます。
3. リクエストを選択し、以下の項目を確認します:
   - **ステータス (Status)**: `200 OK` が返っていれば正常に通信されています。
   - **応答 (Response) タブ**: `{"success": true, "categories": [...]}` という JSON データ構造が返っているか確認します。

### 手順 3: 一括アップロード/登録時のリクエスト確認 (`/api/stamps/batch-update`)
1. スタンプ画像を一括適用ボタンを押した際、**`batch-update`** というリクエストが発生します。
2. ステータスコードを確認します:
   - **`200 OK`**: 正常にサーバー側へ画像データが保存されました。
   - **`413 Payload Too Large`**: アップロード画像サイズが制限を超えています。画像の解像度を少し下げるか圧縮してください。
   - **`404 Not Found`**: リバースプロキシまたは API のマウントパスが一致していません。
   - **`500 Internal Server Error`**: 保存先フォルダ（`data/`, `public/stamps/custom/`）の書き込み権限エラー等が発生しています。

---

## 診断チェックポイントまとめ
1. **ステータスコード `200`**: 正常動作。
2. **`404` エラー時**: `/api/stamps` へのルーティング設定が反映されていないか、Express アプリの再起動が必要です。
3. **`500` または `TypeError`**: `stamps.js` 内部エラーログの確認が必要です。
